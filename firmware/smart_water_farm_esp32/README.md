# อธิบายโค้ดเฟิร์มแวร์ Smart Water Farm ทีละส่วน

ไฟล์ `smart_water_farm_esp32.ino` (3,190 บรรทัด) · บอร์ด ESP32-S3-WROOM-1 N16R8 · เวอร์ชัน `3.0.0-s3-real`  
เลขบรรทัดในเอกสารนี้ตรงกับไฟล์ `smart_water_farm_esp32.ino` ในโฟลเดอร์นี้ เปิดไฟล์คู่กันแล้วกระโดดไปบรรทัดนั้นได้เลย

> 💡 **ภาพรวมใน 4 ประโยค**  
> 1) บอร์ดอ่านค่าน้ำจริงจากเซนเซอร์ (pH, EC/TDS, อุณหภูมิ, ลูกลอยระดับน้ำ) ทุก 5 วินาที  
> 2) ส่งค่าขึ้นคลาวด์ ThingsBoard ทาง WiFi + MQTT ทุก 30 วินาที แล้วเซิร์ฟเวอร์ส่งต่อไป Firebase ให้แอปมือถือแสดงผล  
> 3) แอปสั่งเปิดปั๊ม 5 ตัว / เปลี่ยนโหมด / คาลิเบรต pH ย้อนกลับมาที่บอร์ดได้ (เรียกว่า RPC) และถ้าเปิดโหมด AUTO บอร์ดจะเติมปุ๋ย/ปรับ pH เอง  
> 4) ผูกบอร์ดกับบัญชีผู้ใช้ผ่าน Bluetooth (BLE) + QR บนจอ OLED และถ้าเน็ตหลุด บอร์ดจดข้อมูลเก็บไว้ในหน่วยความจำแฟลชแล้วส่งย้อนหลังทีหลัง

> ⚠️ **กฎเหล็กของโค้ดนี้: ไม่มีค่าปลอม (Zero-Mock)** ถ้าเซนเซอร์ตัวไหนอ่านไม่ได้หรือค่าผิดปกติ บอร์ดจะ ไม่ส่งค่านั้นเลย (ไม่เดาเลข ไม่ส่ง 0) แอปจึงแสดง `--` แทน ส่วน `esp_random()` ใช้แค่สร้างรหัสลับสำหรับจับคู่และหน่วงเวลาเน็ตเท่านั้น ไม่เคยใช้กับค่าเซนเซอร์ (บรรทัด 15-18)

### แผนภาพการทำงาน: setup() ทำครั้งเดียว แล้ว loop() วนตลอด

```text
[ เปิดเครื่อง setup() บรรทัด 2958 ]
        ▼
[ ① ปิดรีเลย์ปั๊มทั้ง 5 ตัวก่อน (กันปั๊มกระตุกตอนบูต) + ตั้งขา LED → ② เปิด Serial 115200 → ③ สร้าง ตัวจับเวลาตัดปั๊ม (esp_timer) ให้ปั๊มแต่ละตัว ]
        ▼
[ ④ ตั้งปุ่ม BOOT + ลูกลอย → ⑤ setupIdentity ตั้งชื่อบอร์ด FARM-xxxxxx จาก MAC → ⑥ setupNvs โหลดค่าที่จำไว้ (WiFi, เจ้าของ, ช่วงค่าเป้าหมาย, คาลิเบรต) → ⑦ ologBegin เตรียมพื้นที่บันทึกออฟไลน์ ]
        ▼
[ ⑧ เริ่ม I2C → หา ADS1115 (0x48) และจอ OLED (0x3C) → ⑨ เริ่มเซนเซอร์อุณหภูมิ DS18B20 → ⑩ setupBle → ⑪ ตั้ง WiFi + MQTT ]
        ▼
[ ⑫ ถ้ายังไม่มีเจ้าของ/ไม่มี WiFi → เปิดหน้าต่างจับคู่ (QR บนจอ) → ⑬ ตั้ง AUTO ให้เริ่มประเมินหลังบูต 5 นาที → ⑭ เปิด Watchdog 20 วินาที ]
        ▼
[ วนทุก ~2 ms loop() บรรทัด 3148 · ทุกฟังก์ชันเป็นแบบ "tick" คือทำงานทีละนิดแล้วรีบออก ไม่มีการรอค้าง ]
        ▼
[ 1. รีเซ็ต watchdog (บอกว่ายังไม่ค้าง) → 2. pumpSafetyTick เช็กความปลอดภัยปั๊ม → 3. buttonTick อ่านปุ่ม BOOT → 4. pendingActionTick ทำคำสั่งรีบูต/รีเซ็ตที่รอไว้ ]
        ▼
[ 5. จัดการหน้าต่างจับคู่ (หมดเวลา 10 นาที / บอร์ดไม่มีเจ้าของเปิดไว้ตลอด) → 6. sensorTick อ่านเซนเซอร์ → 7. serialCmdTick รับคำสั่งคาลิเบรตจากคอม ]
        ▼
[ 8. bleTick Bluetooth → 9. wifiTick WiFi → 10. mqttTick คลาวด์ → 11. offlinePairingTick → 12. ologTick บันทึก/ส่งข้อมูลย้อนหลัง ]
        ▼
[ 13. autoTick โหมด AUTO → 14. pumpSafetyTick (เช็กซ้ำอีกรอบ) → 15. ถ้าต่อคลาวด์อยู่: ส่ง attributes ที่เปลี่ยน + ส่ง telemetry (ทุก 30 วิ หรือทันทีเมื่อค่าเปลี่ยน) ]
        ▼
[ 16. oledTick วาดจอ → 17. ledTick สีไฟสถานะ → พิมพ์ heap ทุก 1 นาที → delay(2) → กลับไปข้อ 1 ↺ ]
```

ทำไมแบ่งเป็น tick: ถ้าฟังก์ชันไหนรอนาน ๆ (เช่นรอเน็ต) งานอื่นจะหยุดหมด รวมถึงการตัดปั๊ม แบบ tick ทำให้ทุกงานได้ทำงานสลับกันหลายร้อยครั้งต่อวินาที

| สิ่งที่อยู่ในส่วนนี้ | หมายความว่า |
| --- | --- |

| บรรทัด 36-38 `#error` | ถ้าเลือกบอร์ดผิด คอมไพล์จะหยุดทันทีพร้อมข้อความเตือน กันแฟลชผิดบอร์ด |

## ส่วน 1 · Pin map แผนที่ขาไฟ (บรรทัด 125-158)

**ทำอะไร:** ตั้งชื่อให้ขา GPIO แต่ละขา ว่าต่อกับอุปกรณ์อะไร ตรงตาม Schematic ใน EasyEDA ถ้าจะย้ายสาย แก้ที่นี่ที่เดียว

| อุปกรณ์ | ขา | หมายเหตุ |
| --- | --- | --- |
| DS18B20 วัดอุณหภูมิน้ำ | IO39 | มี pull-up 4.7kΩ บนบอร์ด ใช้โปรโตคอล 1-Wire |
| ลูกลอยถังหลัก | IO40 | `FLOAT_WATER_PRESENT_LEVEL HIGH` (บรรทัด 132) = มีน้ำเมื่อขาเป็น HIGH (แก้เมื่อ 22 พ.ย. เพราะลูกลอยจริงทำงานกลับด้าน) |
| I2C SDA / SCL | IO16 / IO15 | ความเร็ว 400 kHz ใช้ร่วมกันระหว่าง ADS1115 (0x48) กับจอ OLED (0x3C) |
| pH / TDS | ADS1115 ช่อง A0 / A1 | ESP32 ไม่ได้อ่านตรง ผ่านตัวแปลง ADC 16 บิต |
| ปั๊ม A, B, pH+, pH-, หลัก | IO10, 11, 12, 13, 14 | ขับรีเลย์ผ่านทรานซิสเตอร์ 2N3904 → HIGH = เปิด |
| LED RGB | IO4 / 5 / 6 | แบบ common-anode: LOW = ติด (`LED_ACTIVE_LOW 1`) |
| ปุ่ม BOOT | IO0 | กดค้าง 5 วิ / 10 วิ เพื่อรีเซ็ต |

```cpp
151 |  #define PIN_PUMP_A 10         // ESP32_GPIO10_PUMP1 = nutrient A
152 |  #define PIN_PUMP_B 11         // ESP32_GPIO11_PUMP2 = nutrient B
153 |  #define PIN_PUMP_PH_UP 12     // pH up
154 |  #define PIN_PUMP_PH_DOWN 13   // pH down
155 |  #define PIN_PUMP_MAIN 14      // main circulation pump
```

> ⚠️ ห้ามใช้ GPIO26-32 (ต่อกับแฟลช) และ GPIO33-37 (ต่อกับ PSRAM) บนชิป N16R8 (บรรทัด 29) เพราะจะทำให้บอร์ดค้าง/บูตไม่ขึ้น

## ส่วน 2 · ค่าคาลิเบรตเซนเซอร์ (บรรทัด 160-198)

**ทำอะไร:** เก็บ "ตัวเลขอ้างอิง" ที่ใช้แปลงแรงดันไฟ (โวลต์) จากเซนเซอร์ให้เป็นค่า pH, ppm และกำหนดขอบเขตว่าแรงดันแค่ไหนถือว่าผิดปกติ

| ค่าคงที่ | ค่า | ทำไม |
| --- | --- | --- |
| `PH_DIVIDER_RATIO` | 1.0 | ถ้ามีวงจรแบ่งแรงดันระหว่างโมดูล pH กับ ADS1115 ใส่อัตราส่วนที่นี่ โมดูล pH ใช้ไฟ 5V อาจจ่ายเกิน 3.3V ซึ่งทำ ADS1115 พังได้ (คำเตือนบรรทัด 162-171) |
| `PH_CAL_V7_DEFAULT` / `V4` | 2.50V / 3.05V | แรงดันปกติของโมดูลที่ pH 7 และ pH 4 ใช้จนกว่าจะคาลิเบรตด้วยน้ำยามาตรฐานจริง |
| `PH_CAL_MIN_SPAN_V` | 0.10V | จุด pH 7 กับ pH 4 ต้องห่างกันอย่างน้อย 0.1V ไม่งั้นความชันเพี้ยน (หารด้วยเลขใกล้ 0) |
| `PH_PIN_MIN/MAX_V` | 0.05-3.25V | นอกช่วงนี้ = สายหลุด/โมดูลเสีย ไม่ส่งค่า |
| `TDS_PIN_MIN/MAX_V` | 0.02-2.40V | ~0V = หัววัดอยู่ในอากาศหรือถอดออก ไม่ส่ง "0 ppm" หลอก |
| `ADC_MAX_SPREAD_V` | 0.15V | อ่าน 9 ครั้งแล้วค่ากระจายเกินนี้ = สัญญาณลอย/มีสัญญาณรบกวน ทิ้ง |
| `ADC_MIRROR_V` | 0.03V | ขาที่ไม่มีอะไรต่อ (ลอย) ของ ADS1115 จะ "ก๊อป" ค่าของช่องก่อนหน้า ถ้า A0 กับ A1 เท่ากันเกือบเป๊ะ = มีช่องหนึ่งลอย ทิ้งทั้งคู่ |
| `ADS_SAMPLES` | 9 | อ่าน 9 ครั้งแล้วเอาค่ากลาง (median) ตัดค่ากระโดด |
| `TEMP_MIN/MAX_VALID_C` | -10 ถึง 60°C | อุณหภูมิน้ำนอกช่วงนี้เป็นไปไม่ได้ = อ่านผิด |
| `TEMP_COMP_FALLBACK_C` | 25°C | ใช้ชดเชย TDS เมื่อเซนเซอร์อุณหภูมิเสียเท่านั้น **ไม่ส่งขึ้นแอป** |

## ส่วน 4-5 · ชนิดข้อมูลและตัวแปรกลาง (บรรทัด 250-573)

**ทำอะไร:** ออกแบบ "กล่องเก็บข้อมูล" ของระบบ เช่น ปั๊มหนึ่งตัวต้องจำอะไรบ้าง ค่าเซนเซอร์เก็บยังไง แล้วสร้างตัวแปรกลางที่ทุกส่วนใช้ร่วมกัน

### ชนิดข้อมูลหลัก

| ชื่อ | บรรทัด | เก็บอะไร |

## ส่วน 10 · ประมวลผลเซนเซอร์ (บรรทัด 858-1092)

**ทำอะไร:** หัวใจของการวัดค่าน้ำ ทุก 5 วิจะอ่าน pH, TDS, อุณหภูมิ และลูกลอย กรองสัญญาณรบกวน คำนวณเป็นหน่วยจริง แล้วตัดสินว่าค่านี้ "เชื่อได้" หรือไม่ ถ้าไม่ได้ก็ไม่ส่ง

| ขั้น | ทำอะไร |
| --- | --- |
| 1 | สั่ง DS18B20 เริ่มวัดอุณหภูมิ (ใช้เวลา 750 ms จึงสั่งไว้ก่อนแล้วกลับมาอ่านทีหลัง 800 ms ไม่รอค้าง) |

### การกรองสัญญาณ

• **Median (ค่ากลาง)** ของ 9 ค่า: `medianAndSpread` (873) เรียงค่าแล้วเอาตัวที่ 5 ตัดค่ากระโดดทิ้ง และหา spread = ค่ามาก-ค่าน้อย ถ้า > 0.15V = สัญญาณรบกวน → ทิ้ง

### สูตร pH (เส้นตรง 2 จุด)

```cpp
920 |      float slope = (7.0f - 4.0f) / (phCalV7 - phCalV4);  // pH per volt
921 |      float ph = 7.0f + (S.phSensorV - phCalV7) * slope;
922 |      if (isfinite(ph) && ph >= 0.0f && ph <= 14.0f) {
```

อธิบาย: รู้ว่าน้ำยา pH 7 ให้แรงดัน V7 และ pH 4 ให้ V4 ลากเส้นตรงผ่าน 2 จุดนี้ แล้วแปลงแรงดันที่วัดได้เป็น pH ตัวอย่างค่าปริยาย V7 = 2.50V, V4 = 3.05V → ความชัน = 3 / (2.50-3.05) = -5.45 pH ต่อโวลต์ ถ้าวัดได้ 2.60V → pH = 7 + (0.10 × -5.45) ≈ **6.45** ค่าที่ออกนอก 0-14 ถือว่าผิด ไม่ส่ง

> ⚠️ ตอนนี้ (ตามที่ตัดสินใจ 21 พ.ย., บรรทัด 916-917) บอร์ดส่งค่า pH แม้ยังไม่คาลิเบรตด้วยน้ำยามาตรฐาน โดยใช้เส้นปริยาย ใน Serial จะมีเครื่องหมาย `~` หน้าค่า pH เพื่อเตือนว่ายังไม่คาลิเบรต

### สูตร TDS / EC (สูตร DFRobot + ชดเชยอุณหภูมิ)

```cpp
939 |      float coef = 1.0f + 0.02f * (tC - 25.0f);
940 |      float cv = tdsV / coef;
941 |      float tds = (133.42f*cv*cv*cv - 255.86f*cv*cv + 857.39f*cv) * 0.5f * TDS_K_VALUE;
946 |        S.ec = tds / 500.0f;  // ppm (0.5 scale) -> mS/cm
```

อธิบาย: น้ำอุ่นนำไฟฟ้าดีขึ้นประมาณ 2% ต่อ 1°C จึงหารด้วย `coef` ให้ค่าเหมือนวัดที่ 25°C แล้วแปลงแรงดันเป็น ppm ด้วยสมการกำลังสามจากผู้ผลิต แล้วแปลง ppm เป็น EC (mS/cm) ด้วยการหาร 500 ถ้าเซนเซอร์อุณหภูมิเสีย ใช้ 25°C ชดเชยแทน แต่ `sensor_ok` จะเป็น false

### อุณหภูมิ DS18B20 (บรรทัด 325-419 และ 1050-1072)

เขียนไดรเวอร์ 1-Wire เอง (`owReset, owWriteByte, owReadByte`) เพราะทดสอบแล้วไลบรารี OneWire มองไม่เห็นเซนเซอร์บนขา IO39 ทุกค่าต้องผ่าน 4 ด่าน: ① เซนเซอร์ตอบ (presence) ② ข้อมูลไม่ใช่ 0 หรือ FF ล้วน (สายค้าง) ③ **CRC-8 ถูก** ④ ไบต์ config ถูกต้อง ค่าอุณหภูมิ = raw / 16 และตัดค่า **85.0°C** ทิ้งเสมอ เพราะเป็นค่าตอนเพิ่งจ่ายไฟของชิป ไม่ใช่อุณหภูมิจริง

### ลูกลอย (บรรทัด 1076-1091)

## ส่วน 13 · โหมด AUTO เติมปุ๋ย/ปรับ pH เอง (บรรทัด 1229-1343)

**ทำอะไร:** เมื่อเปิด AUTO บอร์ดจะดูแลน้ำเองเป็น **state machine 3 สถานะ**

```text
[ AS_WAIT (รอ) ทุก 5 นาที เช็กค่า: เซนเซอร์ครบและน้ำในถังพอไหม? ถ้าไม่ → ข้ามรอบนี้ pH > สูงสุด → คิว pH- · pH < ต่ำสุด → คิว pH+ · EC < ต่ำสุด → คิว A แล้ว B ]
        ▼ มีงานในคิว
[ AS_DOSING (เติม) เปิดปั๊มหลักวน 5 วิก่อน → ปิด → เปิดปั๊มในคิว ทีละตัว ตัวละ 2 วิ เว้น 1 วิ (ถ้าระหว่างนี้เซนเซอร์เสียหรือน้ำหมด → ยกเลิกที่เหลือ) ]
        ▼ ครบคิว
[ AS_MIXING (ผสม) เปิดปั๊มหลักวนน้ำ 5 นาทีให้สารผสมทั่ว แล้วกลับไป WAIT และเช็กใหม่ทันที ]
```

```cpp
1275 |        if (S.ph > targetPhMax) autoQueue[autoQueueLen++] = P_PHDOWN;
1276 |        else if (S.ph < targetPhMin) autoQueue[autoQueueLen++] = P_PHUP;
1277 |        if (S.ec < targetEcMin) {
1278 |          autoQueue[autoQueueLen++] = P_A;
1279 |          autoQueue[autoQueueLen++] = P_B;
1280 |        }
```

| `autoTick` (1257) | ตัว state machine ข้างบน ถ้าปิด AUTO หรือบอร์ดไม่มีเจ้าของ → รีเซ็ตกลับ WAIT |
| `autoReset` (1246) | หยุดปั๊มเคมีที่ AUTO เปิดไว้ ล้างคิว ตั้งเวลาเช็กครั้งต่อไป |
| `autoEnsureMainUntil` (1234) | ให้ปั๊มหลักเปิดถึงเวลาที่กำหนด (ไม่ตัดสั้นถ้าผู้ใช้เปิดไว้นานกว่า, ไม่เปิดถ้าน้ำหมด) |

**ทำไมเติมทีละ 2 วิ แล้วรอ 5 นาที:** สารเคมีต้องใช้เวลาผสม ถ้าวัดทันทีหลังเติมค่าจะยังไม่เปลี่ยน แล้วระบบจะเติมซ้ำจนเกิน (overshoot) การเติมน้อย ๆ แล้วรอผสมจึงปลอดภัยกว่า **ทำไมปั๊ม A คู่กับ B เสมอ:** ปุ๋ย AB ต้องใส่คู่กันในสัดส่วนเท่ากัน

ข้อจำกัดที่ควรรู้: AUTO แก้ได้เฉพาะ EC ต่ำ (เติมปุ๋ย) ถ้า EC สูงเกินต้องเติมน้ำเปล่าเอง และช่วงอุณหภูมิใช้แค่แสดง/แจ้งเตือน บอร์ดไม่ได้ควบคุมอุณหภูมิ · แอปเห็นสถานะผ่าน key `auto_phase` (idle/dosing/mixing), `auto_reason` เช่น "pH 7.10 > 6.50", `auto_mix_left` วินาทีที่เหลือ

## ส่วน 15 · รับคำสั่งจากแอป: Shared attributes + RPC (บรรทัด 1456-1745)

### mqttCallback (1717) ประตูรับข้อความ

• `bind_owner` มีชื่อ → ผูกบอร์ด (ถ้า bind\_ts ไม่ใช่ของเก่า) · `bind_owner` ว่าง → ยกเลิกผูก แล้วลืม WiFi

## ส่วน 16 · BLE จับคู่ผ่านมือถือ (บรรทัด 1746-2113)

**ทำอะไร:** ให้มือถือเชื่อมกับบอร์ดผ่าน Bluetooth Low Energy เพื่อ **พิสูจน์ว่าอยู่หน้าบอร์ดจริง** แล้วส่งชื่อ/รหัส WiFi ให้บอร์ด ใช้ Service `0xFFFF` และ Characteristic `0xFF01` ตัวเดียว (อ่าน/เขียน/แจ้งเตือน)

> ⚠️ **หลักสำคัญ:** callback ของ BLE (`ServerCallbacks`, `CharCallbacks.onWrite`) ทำงานใน task ของ Bluetooth เอง จึง**แค่ตั้งธงและโยนข้อความเข้าคิว** (`xQueueSend` บรรทัด 1772) งานจริงทำใน loop() ผ่าน `bleTick` กันสองงานแย่งตัวแปรกันจนพัง

### ขั้นตอนการจับคู่ (handleBleCommand บรรทัด 1918)

| ขั้น | แอปส่ง | บอร์ดทำ |
| --- | --- | --- |
| 1a. ยืนยันด้วย QR | `{"cmd":"auth","c":"รหัสลับ"}` | เทียบกับ `claimSecret` ด้วย `constantTimeEq` ถูก → `auth_ok` · ผิด 3 ครั้ง → ล็อก 5 นาที |
| 1b. หรือยืนยันด้วยเลข 6 หลัก | `start_verify` แล้ว `verify_code` | จอ OLED โชว์เลข 6 หลัก ผู้ใช้พิมพ์ในแอป ถูก → `verified` · ผิด 2 ครั้ง → ล็อก 5 นาที |
| 2. สแกน WiFi | `{"cmd":"scan_wifi"}` | สแกนแบบไม่รอ เก็บสูงสุด 12 เครือข่าย ตัดชื่อซ้ำ เรียงสัญญาณแรงก่อน |
| 3. ส่ง WiFi | `{"ssid":"...","pass":"..."}` | ต้องยืนยันตัวแล้วเท่านั้น (ไม่งั้น `UNAUTHORIZED`) แล้วเริ่มทดสอบต่อ WiFi |

**สถานะที่บอร์ดตอบ:** `buildBleStatus` (1790) สร้าง JSON เช่น `wifi_status` (idle/testing/ok/error), `error` (ERR\_WIFI\_WRONG\_PASSWORD, ERR\_WIFI\_NO\_AP\_FOUND ...), `ip`, `attemptsLeft`, รายชื่อ WiFi โดยตัดรายการท้าย ๆ ให้ไม่เกิน 500 ไบต์ (ขีดจำกัด BLE 512)

**bleTick (2072):** จัดการเหตุการณ์ต่อ/หลุด อ่านคิวคำสั่ง และ **โฆษณาตัว (advertise) เฉพาะตอนเปิดหน้าต่างจับคู่และยังไม่มีใครต่อ** นอกนั้นซ่อนตัว ลดช่องโหว่

> ❓ **ทำไมเลข 6 หลักไม่ส่งทาง BLE:** เวอร์ชันเก่าให้เลือก 1 ใน 3 ตัวเลขที่ส่งผ่าน BLE ใครอยู่ใกล้ ๆ ก็เดาถูก 1/3 แล้วได้รหัสลับไป ตอนนี้เลขโชว์บนจอเท่านั้น ต้องมองเห็นบอร์ดจริงถึงจะรู้ (บรรทัด 628-629)

## ส่วน 17 · WiFi และ MQTT ต่อใหม่อัตโนมัติ (บรรทัด 2114-2360)

**ทำอะไร:** ดูแลให้บอร์ดออนไลน์อยู่เสมอ ถ้าหลุดก็ต่อใหม่ โดยไม่ทำให้ loop() ค้าง

### wifiTick (2117) มี 4 งาน

① **ทดสอบรหัส WiFi ใหม่จาก BLE**: ลองต่อสูงสุด 3 ครั้ง ครั้งละ 13 วิ (WiFi กับ BLE ใช้เสาอากาศร่วมกัน ครั้งแรกมักพลาด) ถ้ารหัสผิดซ้ำ 2 ครั้งติดหยุดลองทันที สำเร็จ → บันทึกลง NVS · ล้มเหลว → แปลงเหตุผลเป็นรหัส error ให้แอปโชว์  
② **สแกน WiFi** แบบ async  
③ **ตรวจการเปลี่ยนสถานะ**: เพิ่งต่อได้ → ขอเวลาจริงจาก NTP (`configTime` บรรทัด 2254) ใช้ประทับเวลา log ออฟไลน์  
④ **ต่อ WiFi ที่จำไว้ใหม่แบบ Exponential Backoff + Jitter**

```cpp
2266 |      WiFi.begin(wifiSsid, wifiPass);
2267 |      wifiNextAttemptAt = now + withJitter(wifiBackoffMs);
2268 |      wifiBackoffMs = wifiBackoffMs * 2 > WIFI_BACKOFF_MAX_MS ? WIFI_BACKOFF_MAX_MS : wifiBackoffMs * 2;
```

อธิบาย: ต่อไม่ติด รอ 4 วิ → 8 → 16 → 32 → 60 วิ (เพดาน) บวกลบสุ่ม 20% ไม่ถล่มเราเตอร์ และไม่เปลืองพลังงาน

### mqttTick (2286) ต่อ ThingsBoard 2 ขั้น

ขั้น 1: แปลงชื่อเซิร์ฟเวอร์เป็น IP (DNS) แยกรอบ เพราะอาจใช้เวลาหลายวินาที (ป้อน watchdog ก่อน) · ขั้น 2: `mqtt.connect(deviceId, tbToken)` ใช้ Token เป็น username timeout 3 วิ ล้มเหลวก็ backoff 1 → 2 → 4 ... → 60 วิ  
ต่อได้แล้ว `onMqttConnected` (2273): subscribe RPC + attributes, ส่ง attributes, ขอค่าตั้ง, ส่ง claim, ส่ง telemetry ทันที

### offlinePairingTick (2338)

บอร์ดมีเจ้าของแต่ WiFi หายเกิน 2 นาที (เช่นเปลี่ยนเราเตอร์) → เปิดหน้าต่างจับคู่เอง ให้ส่ง WiFi ใหม่ผ่านแอปได้โดยไม่ต้องกดปุ่ม และยังพยายามต่อ WiFi เดิมไปด้วย WiFi กลับมาเมื่อไรก็ปิดหน้าต่าง

| `OLOG_INTERVAL_MS` | 60 วิ | จด 1 แถวต่อนาที (หลุดสั้นกว่า 1 นาทีไม่จด) |
| `OLOG_MAX_ROWS` | 200,000 แถว | × 44 ไบต์ = 8.8 MB บน FFat ≈ **138 วัน** เต็มแล้วเขียนทับแถวเก่าสุด (ring buffer) |
| `OLOG_RAM_CAP` | 10,080 แถว | พักใน PSRAM ได้ 7 วัน ระหว่างรอเวลาจริงจาก NTP |
| `OLOG_FLASH_BATCH` | 10 แถว | เขียนแฟลชทีละ 10 แถว (~10 นาที) ถนอมอายุแฟลช |
| `OLOG_SEND_BATCH` / `GAP` | 10 แถว / 2 วิ | ส่งย้อนหลังข้อความละ 10 แถว เว้น 2 วิ ไม่ชนลิมิตของ ThingsBoard |
| `OLOG_AFTER_CONNECT_MS` | 5 วิ | ต่อติดแล้ว ส่งค่าปัจจุบันก่อน 5 วิ แล้วค่อยส่งของเก่า |

### ฟังก์ชันหลัก

• `ologBegin`: จองหน่วยความจำ PSRAM, mount FFat (ครั้งแรกจะฟอร์แมต), ตรวจว่าตำแหน่ง index ใน NVS สอดคล้องกับไฟล์ ถ้าไม่ เริ่มไฟล์ใหม่  
• `ologMakeRec`: สร้าง 1 แถว ค่าที่ไม่ valid เก็บเป็น `NAN` (ไม่เดา) แล้วคำนวณ CRC  
• `ologConvertRelative`: ถ้าจดตอนยังไม่รู้เวลาจริง จะเก็บเป็น "เวลานับจากเปิดเครื่อง" ไว้ พอ NTP ตอบก็แปลงย้อนเป็นเวลาจริง (`r.ts = e - (up - at)` บรรทัด 2502)  
• `ologFlushRam`: ย้ายแถวจาก RAM ลงไฟล์ `/olog.bin`  
• `ologSendBatch`: อ่านทีละ 10 แถว **แถวไหน CRC ไม่ตรงทิ้ง** ไม่ส่งค่าเสีย แต่ละแถวติดธง `"offline_log": true` ให้ rule chain บนคลาวด์ไม่ส่งแจ้งเตือนย้อนหลัง  
• `ologTick`: ออฟไลน์ → จดทุกนาที · ออนไลน์ → ทยอยส่ง เสร็จแล้วส่งค่าปัจจุบันซ้ำ 1 ครั้ง

> ❓ **ถ้าไฟดับก่อนรู้เวลาจริงล่ะ?** แถวที่ยังไม่มีเวลาจริงอยู่ใน RAM จะหายไป **ตั้งใจออกแบบแบบนี้** เพราะไม่มีเวลาจริง = ไม่รู้ว่าค่านั้นเป็นของเวลาไหน ใส่กราฟผิดตำแหน่งแย่กว่าไม่มี (บรรทัด 2363-2366)

## ส่วน 18 · จอ OLED (บรรทัด 2678-2803)

**ทำอะไร:** แสดงผลบนจอ 128×64 จุด เลือกหน้าจอตามสถานะ (ลำดับความสำคัญจากบนลงล่าง)

| สถานการณ์ | จอแสดง |
| --- | --- |
| กดปุ่ม BOOT ค้าง ≥ 1 วิ | นับวินาที บอกว่าปล่อยตอนนี้จะเกิดอะไร (5 วิ รีเซ็ต WiFi / 10 วิ รีเซ็ตโรงงาน) |
| มือถือต่อ BLE แต่ยังไม่ยืนยันตัว | "BLE VERIFY CODE" + เลข 6 หลักตัวใหญ่ |
| หน้าต่างจับคู่เปิด | **QR code** เต็มจอ ข้างในเป็น `{"d":ชื่อบอร์ด,"c":รหัสลับ,"m":MAC บลูทูธ}` ให้แอปสแกน |
| ปกติ | ชื่อบอร์ด · WiFi/Cloud OK หรือ -- · เจ้าของ · pH, EC · อุณหภูมิ + ถัง OK/LOW · โหมด + ปั๊มที่เปิด (M A B + -) · บรรทัดเตือน เช่น NO TB TOKEN!, ADS1115 NOT FOUND, SENSOR CHECK |

`oledTick` วาดใหม่ทุก 1 วิ หรือเร็วขึ้น (ทุก 0.25 วิ) ถ้ามีธง `oledDirty` · QR ใช้เวอร์ชัน 3 (29×29 จุด) ขยาย 2 เท่า = 58 พิกเซล ตัด ":" ออกจาก MAC ให้ข้อมูลสั้นพอใส่ได้

### ledTick: สีไฟบอกสถานะ (เช็กจากบนลงล่าง)

| สี | ความหมาย |
| --- | --- |
| ม่วงกะพริบ | กำลังกดปุ่ม BOOT ค้าง |
| น้ำเงินกะพริบ | เปิดหน้าต่างจับคู่อยู่ |

**buttonTick (2818):** นับเวลากดปุ่ม BOOT · ค้าง 5-10 วิแล้วปล่อย → `bootPairingReset` · ค้างถึง 10 วิ → แจ้งคลาวด์ว่ายกเลิกผูกแล้วรีเซ็ตโรงงาน

## ส่วน 20 · setup() และ loop() (บรรทัด 2879-3190)

**ทำอะไร:** จุดเริ่มต้นของโปรแกรม `setup()` ทำครั้งเดียวตอนเปิดเครื่อง `loop()` วนไปเรื่อย ๆ (ดูแผนภาพหน้าแรก)

### ฟังก์ชันเตรียมระบบ

| ฟังก์ชัน | ทำอะไร |
| --- | --- |
| `setupIdentity` (2882) | ตั้งชื่อบอร์ด `FARM-` + 3 ไบต์ท้ายของ MAC (ไม่ซ้ำกันแต่ละบอร์ด) และอ่าน MAC บลูทูธใส่ QR |
| `setupNvs` (2895) | โหลดค่าที่จำไว้ทั้งหมด ลบ token เก่าที่เคยเก็บใน NVS (กัน token ที่หลุดค้างอยู่) ถ้าไม่มีรหัสลับสร้างใหม่ โหมดปริยาย **MANUAL** (ปลอดภัยจนกว่าจะคาลิเบรต) |
| `setupBle` (2929) | สร้าง BLE server ชื่อ = deviceId, ตั้ง MTU 517 (ส่งข้อความยาวได้), ตั้งข้อมูลโฆษณาให้แอปค้นเจอด้วย UUID 0xFFFF |

### จุดสำคัญใน setup() (2958)

```cpp
2960 |    for (int i = 0; i < PUMP_COUNT; i++) {
2961 |      digitalWrite(pumps[i].pin, LOW);   // สั่ง LOW ก่อนเป็น OUTPUT
2962 |      pinMode(pumps[i].pin, OUTPUT);
2963 |      digitalWrite(pumps[i].pin, LOW);   // ย้ำอีกครั้ง → ปั๊มไม่กระตุกตอนบูต
2964 |    }
```

ตั้ง WiFi เอง: `WiFi.persistent(false)` + `setAutoReconnect(false)` เพราะให้ `wifiTick` คุมการต่อใหม่แบบ backoff เอง · MQTT buffer 4096 ไบต์ (พอสำหรับ log ย้อนหลัง 10 แถว) keep-alive 30 วิ · สุดท้ายเปิด **Task Watchdog 20 วิ** ถ้า loop ไม่รายงานตัวเกิน 20 วิ ชิปรีบูตเอง (ปั๊มดับเพราะขาเป็น LOW ตอนรีเซ็ต)

### loop() (3148)

```cpp
3149 |    esp_task_wdt_reset();                 // "ยังไม่ค้างนะ"
3152 |    pumpSafetyTick(now);                  // ความปลอดภัยมาก่อนเสมอ
3164 |    sensorTick(now);  serialCmdTick();  bleTick(now);  wifiTick(now);  mqttTick(now);
3169 |    ologTick(millis());
3173 |    autoTick(now);
3174 |    pumpSafetyTick(now);                  // เช็กซ้ำหลังงานเน็ตที่อาจกินเวลา
3178 |      if (isBound && (telemetryDirty || (now - lastTelemetryAt) >= TELEMETRY_INTERVAL_MS)) sendTelemetry();
3189 |    delay(2);
```

(ตัดมาเฉพาะบรรทัดหลัก) · `delay(2)` แค่ 2 ms เพื่อคืนเวลาให้ task อื่น (BLE/WiFi รันใน task ของตัวเอง) ไม่ได้บล็อกระบบ

## ส่วนเสริม · คาลิเบรต pH ผ่านคอม (Serial) (บรรทัด 3062-3146)

**ทำอะไร:** เปิด Serial Monitor (115200) พิมพ์คำสั่งแล้วกด Enter เพื่อคาลิเบรตหัววัด pH โดยไม่ต้องใช้แอป บันทึกที่เดียวกับ RPC `calibratePh`

| คำสั่ง | ทำอะไร |
| --- | --- |
| `calshow` | ดูค่าคาลิเบรตปัจจุบัน + ความชัน mV/pH |
| `cal7` / `cal4` | จุ่มหัววัดในน้ำยา pH 7 / pH 4 รอจนหน้าต่างเต็ม 12/12 แล้วบันทึกค่าเฉลี่ย (ยังไม่เต็ม = ปฏิเสธ) |
| `calset <v7> <v4>` | ใส่โวลต์ 2 จุดตรง ๆ (0.05-3.25V ห่างกัน ≥ 0.10V) |
| `caldefault` | กลับไปใช้เส้นปริยาย |
| `fast` / `slow` | อ่านทุก 1 วิ (10 นาที) สำหรับหมุนปรับ trimmer บนโมดูล / กลับเป็น 5 วิ |

Serial พิมพ์บรรทัด `[PH] raw=... avg=... sd=... n=12/12 STABLE pH=...` ทุกรอบ รอจนขึ้น **STABLE** (ส่วนเบี่ยงเบน ≤ 0.003V) ค่อยสั่ง cal

### คำถามที่อาจารย์น่าจะถาม (ตอบสั้น)

| คำถาม | คำตอบ |
| --- | --- |
| ถ้าเน็ตหลุดตอนปั๊มเปิด ปั๊มจะเปิดค้างไหม | ไม่ ทุกครั้งที่เปิดปั๊มจะตั้ง esp\_timer ตัดไฟเองตามเวลา ทำงานแยกจาก loop และมีเช็กสำรองใน pumpSafetyTick อีกชั้น ปั๊มเคมีเปิดได้สูงสุด 10 วิ |
| ถ้าเซนเซอร์หลุดจะเกิดอะไร | ค่านั้นไม่ถูกส่ง (key หาย) แอปโชว์ `--`, sensor\_ok = false, AUTO หยุดเติม, LED เขียวกะพริบแดง, OLED ขึ้น SENSOR CHECK |
| ทำไมเปิดปั๊มได้ทีละตัว | แหล่งจ่ายไฟรับกระแสกระชากของมอเตอร์ได้ทีละตัว โค้ดบังคับ 3 ที่: startPump ปฏิเสธ, RPC ตอบ PUMP\_BUSY, pumpSafetyTick ปิดหมดถ้าพบเกิน 1 ตัว |
| กันคนอื่นมายึดบอร์ดยังไง | ต้องมีรหัสลับใน QR หรือเห็นเลข 6 หลักบนจอจริง, ผิด 3 ครั้ง (หรือเลขผิด 2 ครั้ง) ล็อก 5 นาที, เทียบรหัสแบบ constant-time, ยกเลิกผูกแล้วสุ่มรหัสใหม่ |

| ข้อมูลช่วงออฟไลน์หายไหม | ไม่หาย จดทุก 1 นาทีลงแฟลช 9.9MB ได้ ~138 วัน ส่งย้อนหลังพร้อมเวลาจริงจาก NTP |
